# Design

Migration 9 extends the existing configuration transaction/receipt boundary with optional Role policies, singleton Global/Planner policies and GitHub metadata plus encrypted private-key storage. Add JSON Schema definitions for complete targets/policies and common model/thinking fields. Configuration remains versioned as one small single-Owner snapshot. Policies only affect future context/dispatch selection, not already-stored launch envelopes.

GitHub App secrets are encrypted with AES-256-GCM using a domain-separated HKDF key derived from the service signing secret, unique random IV and fixed versioned associated data. App/installation IDs are authenticated associated data too. Retain encrypted key and fingerprint in PostgreSQL; never persist original secret-bearing envelope, expose PEM/token in reads, or echo provider errors. Key rotation requires re-entering the provider key; document this limitation and backup boundary. Production supplies signing secret through existing private file; tests inject synthetic keys. Private-key validation uses Node crypto RSA key parsing/signing. A distinct POST command saves it; receipt hashes exact canonical content and contains only version/entity identity. Empty key on metadata edit preserves the existing key.

GitHub adapter uses fixed https://api.github.com, pinned API version, no redirects, timeouts and bounded JSON. Short-lived RS256 App JWT obtains an installation token with contents:read and metadata:read; token is used only in memory to read one bounded repository page, never sent to Runner/Agent/UI. Validate repository response fields and return provider-neutral resource suggestions with opaque IDs/default branch. A repository page is not a remote-publication readiness claim. No provider writes beyond ephemeral token issuance occur.

Runner installation reports use an optional runtimes field on the existing ready frame, preserving old clients. Server updates a complete per-Runner registry snapshot only under the current channel/instance lock; offline status is derived from Runner connection/heartbeat and retained observation time. Discovery occurs on reconnect and does not block recovery correctness if unavailable. The narrow privileged helper accepts a new field-free discover action and invokes only the fixed OpenCode --version command as the fixed execution UID/GID with bounded output/deadline and explicit environment/cwd; never owner CLI as root. Report model field support and an empty discovered catalog, permitting manual model entry. No arbitrary executable or user can be selected by helper input.

Changes: configuration/API/schema/migration, GitHub adapter, ready-frame handling and Go helper/control/daemon discovery. Tests cover secret encryption/no echo/replay/rotation errors, scoped provider requests and failure sanitization, malformed keys/policies, Runner fencing/omitted report compatibility and fixed discovery permissions. Deploy new schema/server before new Runner; no live service replacement during this task. No destructive down migration.
